# BANK_LEDGER_JOURNAL_DRAFT_TEMPLATE.md

## 目标

这份模板用于定义：银行流水在完成标准化和业务归类后，应如何输出“候选记账分录草稿”。

这里的关键词是：**草稿**。

它不是正式凭证，不直接等于最终入账结果。它的作用是：

- 给出可复核的候选分录
- 暴露判断依据和不确定项
- 将高频流水先结构化处理
- 把复杂例外项留给人工确认

## 输出原则

- 一条流水可以对应一条或多条候选分录草稿
- 分录必须保留原始流水追溯信息
- 分录必须保留业务分类和判断依据
- 如果无法稳定生成分录，应明确标注待人工确认
- 不允许把推测结果伪装成正式会计结论

## 当前核算口径

- 当前企业为小规模纳税人
- 当前默认按小企业会计准则给出候选分录
- 如果未来升级为一般纳税人并切换为企业会计准则，需同步调整候选科目与说明

## 推荐输出表结构

建议每条候选分录至少包含以下字段：

| 字段名 | 是否必填 | 说明 |
| --- | --- | --- |
| `source_file_name` | 是 | 来源文件 |
| `source_row_number` | 是 | 来源行号 |
| `transaction_date` | 是 | 交易日期 |
| `bank_account_name` | 是 | 本方银行账户 |
| `summary` | 是 | 原始摘要 |
| `counterparty_name` | 否 | 对方户名 |
| `net_amount` | 是 | 原始净额 |
| `business_type_candidate` | 是 | 归类结果 |
| `classification_confidence` | 是 | 归类置信度 |
| `entry_group_id` | 是 | 同一笔流水对应的分录组 ID |
| `entry_line_no` | 是 | 分录行号 |
| `debit_account_candidate` | 否 | 候选借方科目 |
| `credit_account_candidate` | 否 | 候选贷方科目 |
| `entry_amount` | 是 | 分录金额 |
| `entry_explanation` | 是 | 为什么建议这组分录 |
| `requires_manual_review` | 是 | 是否需人工复核 |
| `manual_review_reason` | 否 | 人工复核原因 |
| `review_status` | 是 | 默认 `pending_review` |

## 推荐输出层次

建议一批处理结果至少拆成 3 部分：

### A. 已生成候选分录草稿

特点：

- 业务类型明确
- 方向明确
- 候选科目较稳定
- 仍保留待人工复核标记能力

### B. 低置信度分录草稿

特点：

- 已有候选方向和业务类型
- 但科目仍需确认
- 应单独归档，避免直接混入高置信度结果

### C. 无法生成分录的流水

特点：

- 分类不明
- 关键信息缺失
- 无法给出稳定候选分录

## 建议分录映射模板

以下只是候选映射模板，不等于正式账务规则。

### 1. 销售回款 `sales_receipt`

候选思路：

- 借：银行存款
- 贷：应收账款 / 主营业务收入（取决于你们账务口径）

建议备注：

- 如果没有应收对象映射，不要直接强判收入

### 2. 供应商付款 `vendor_payment`

候选思路：

- 借：应付账款 / 预付账款 / 库存商品 / 原材料 / 采购相关科目
- 贷：银行存款

注意：

- 如果已知为 `1688` / 支付宝渠道的供货款，可优先归入供应商付款
- 若仅能确认“供货款”，但无法判断是预付款还是结算款，应保留多个候选借方科目

### 3. 员工报销付款 `staff_reimbursement`

候选思路：

- 借：管理费用 / 销售费用 / 研发费用 / 其他应收款
- 贷：银行存款

注意：

- 如果费用归属不明确，应保留候选而不是强判

### 4. 员工备用金 `staff_advance`

候选思路：

- 借：其他应收款-员工
- 贷：银行存款

### 5. 工资社保个税 `salary_social_tax`

候选思路：

- 借：应付职工薪酬-工资 / 应付职工薪酬-社保 / 应付职工薪酬-公积金 / 应交税费
- 贷：银行存款

注意：

- 在当前公司口径下，工资、社保、公积金采用“先计提、后支付”
- 因此银行付款流水阶段，应优先视为冲减已计提负债，不建议在付款阶段再次直接计入费用

### 6. 税费缴纳 `tax_payment`

候选思路：

- 借：应交税费
- 贷：银行存款

### 7. 银行手续费 `bank_fee`

候选思路：

- 借：财务费用-手续费
- 贷：银行存款

### 8. 内部转账 `internal_transfer`

候选思路：

- 借：其他货币资金 / 内部往来 / 银行存款-另一个账户
- 贷：银行存款-当前账户

注意：

- 内部转账最需要账户映射规则支持

### 9. 借款/还款 `loan_borrow_repay`

候选思路：

- 借：短期借款 / 其他应付款 / 其他应收款
- 贷：银行存款

或反向，取决于实际资金方向。

### 10. 股东注资 `capital_injection`

候选思路：

- 借：银行存款
- 贷：实收资本 / 资本公积 / 其他应付款-股东投入

注意：

- 这类交易通常必须人工复核，确认是资本金、股东借款还是其他性质
- 如果同一主体同时具备股东与员工身份，应按交易用途判断，不应仅按主体身份硬判

### 11. 利息收入 `interest_income`

候选思路：

- 借：银行存款
- 贷：财务费用-利息收入（红字）/ 利息收入

### 12. 小额打款验证 `verification_deposit`

候选思路：

- 借：银行存款
- 贷：其他应付款 / 待确认科目

注意：

- 若金额极小、对手方为企业账户，且场景符合开户或验证流程，可优先按验证打款处理
- 不建议直接并入正式收入

### 13. 投资资金划转 `investment_fund_transfer`

候选思路：

- 借：交易性金融资产 / 其他货币资金 / 投资相关待确认科目
- 贷：银行存款

注意：

- 若公司尚未明确投资记账口径，应强制人工复核

## 建议结果文件拆分

建议至少输出 3 张表或 3 个文件：

- `journal_draft_high_confidence`
- `journal_draft_pending_review`
- `journal_draft_unresolved`

如果只输出一个文件，也建议增加字段区分。

## 建议输出示例结构

```text
entry_group_id: JL-20260416-0001
entry_line_no: 1
business_type_candidate: bank_fee
classification_confidence: high
debit_account_candidate: 财务费用-手续费
credit_account_candidate: 银行存款
entry_amount: 25.00
entry_explanation: 摘要包含“手续费”，方向为流出，金额与费用类交易特征一致
requires_manual_review: false
review_status: pending_review
```

## 最低通过标准

一条候选分录草稿至少要满足：

- 能追溯到原始流水
- 有业务分类结果
- 有候选借贷方向
- 有金额
- 有解释说明
- 有是否需要人工复核的标记
