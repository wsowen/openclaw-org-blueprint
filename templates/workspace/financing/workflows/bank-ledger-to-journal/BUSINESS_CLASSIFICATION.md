# BANK_LEDGER_BUSINESS_CLASSIFICATION.md

## 目标

这份模板用于定义：标准化后的银行流水，如何被归类为可记账的业务类型。

归类的目标不是一次性判断到最终会计处理，而是先把流水归入足够稳定的业务篮子，方便后续生成候选分录草稿。

## 归类原则

- 先判断业务性质，再映射科目
- 依据必须来自摘要、对方户名、交易方向、金额特征、历史规则或人工确认
- 归类结果要附带置信度
- 归类失败时，必须输出“待人工确认”，不能硬猜

## 推荐一级业务分类

建议至少支持以下一级分类：

| 业务分类 | 说明 |
| --- | --- |
| `sales_receipt` | 销售回款/客户付款 |
| `vendor_payment` | 供应商付款/采购款 |
| `staff_reimbursement` | 员工报销付款 |
| `staff_advance` | 员工备用金/借款 |
| `salary_social_tax` | 工资、社保、公积金、个税 |
| `tax_payment` | 税费缴纳 |
| `bank_fee` | 银行手续费/平台手续费 |
| `internal_transfer` | 公司内部账户之间转账 |
| `loan_borrow_repay` | 借款、还款、拆借 |
| `capital_injection` | 股东注资、资本金注入 |
| `refund_or_reversal` | 退款、冲销、退汇、红字类交易 |
| `interest_income` | 存款利息等利息收入 |
| `verification_deposit` | 小额打款验证、账户验证入账 |
| `investment_fund_transfer` | 与投资账户相关的资金划转 |
| `other_or_unknown` | 无法稳定识别 |

## 建议判断依据字段

每次归类建议至少检查：

- `summary`
- `counterparty_name`
- `normalized_direction`
- `net_amount`
- `bank_account_name`
- `remark`
- 历史规则映射
- 已知客户/供应商/员工名单

## 归类输出字段

每一条流水在归类阶段建议输出：

- `business_type_candidate`
- `classification_confidence`，建议取值：`high` / `medium` / `low`
- `classification_basis`
- `requires_manual_review`
- `manual_review_reason`

## 建议归类规则模板

### 1. 销售回款 `sales_receipt`

常见依据：

- 方向为流入
- 摘要包含“货款”“回款”“销售款”“客户付款”等关键词
- 对方户名匹配客户名单

建议判断：

- 同时满足关键词和客户名单：`high`
- 只满足其中之一：`medium`
- 仅靠金额猜测：不建议直接归类

### 2. 供应商付款 `vendor_payment`

常见依据：

- 方向为流出
- 摘要包含“货款”“采购”“结算款”“合同款”等关键词
- 对方户名匹配供应商名单

### 3. 员工报销付款 `staff_reimbursement`

常见依据：

- 方向为流出
- 对方户名为个人
- 摘要包含“报销”关键词

注意：

- 如果只是个人户名，没有“报销”依据，应降低置信度
- 如果公司有员工名单，应结合名单判断

### 4. 员工备用金/借款 `staff_advance`

常见依据：

- 方向为流出
- 对方户名为员工或个人
- 摘要包含“备用金”“借款”“预支”等关键词

### 5. 工资社保个税 `salary_social_tax`

常见依据：

- 方向通常为流出
- 摘要包含“工资”“代发”“社保”“公积金”“个税”
- 对方户名可能为代发平台、税务机关或社保机构

### 6. 税费缴纳 `tax_payment`

常见依据：

- 方向为流出
- 摘要或对方主体显示税务机关、税费、增值税、附加税、个税等

### 7. 手续费 `bank_fee`

常见依据：

- 方向为流出
- 摘要包含“手续费”“服务费”“结算费”“账户管理费”等
- 金额通常较小，但不能只按金额判断

### 8. 内部转账 `internal_transfer`

常见依据：

- 对方户名与本公司主体一致或为已知关联内部账户
- 摘要包含“内部转账”“资金归集”“账户互转”等

注意：

- 内部转账通常最需要名单支持
- 若无法确认是否内部账户，应人工复核

### 9. 借款/还款 `loan_borrow_repay`

常见依据：

- 摘要包含“借款”“还款”“拆借”“归还”
- 对方为自然人、股东、关联方或金融机构

### 10. 股东注资 `capital_injection`

常见依据：

- 方向为流入
- `用途` 或 `备注` 包含“股东注资”“出资”“资本金”等关键词
- 对方主体为股东或关联自然人

### 11. 退款/冲销 `refund_or_reversal`

常见依据：

- 摘要包含“退款”“退汇”“冲正”“冲销”“原路退回”等
- 方向与原始业务相反

### 12. 利息收入 `interest_income`

常见依据：

- 摘要包含“存款利息”“利息收入”等关键词
- 方向为流入
- 对方主体通常为银行

### 13. 小额打款验证 `verification_deposit`

常见依据：

- 摘要为“网络转入”“跨行代付”等
- `用途` 或 `备注` 包含“打款验证”“账户验证”等关键词
- 金额通常极小
- 对方主体通常为支付平台

### 14. 投资资金划转 `investment_fund_transfer`

常见依据：

- 对方为券商、基金平台、期货公司、托管账户或投资账户
- 摘要含申购、赎回、入金、出金、保证金等关键词

注意：

- 这类资金可以先归类，但具体投资分析仍应交由 `Athena / Investment Analyst`

### 15. 无法识别 `other_or_unknown`

以下情况应优先归到此类：

- 摘要过短或无明确业务含义
- 对方主体无法识别
- 同时命中多个互斥规则
- 信息不足以支撑稳定判断

## 样本驱动优先规则（`info1776258323868.xls`）

基于真实样本，以下规则应优先于泛化关键词判断：

### A. `财税库行-税费/社保`

- 如果 `备注` 含“个人所得税”“印花税”等税种关键词：归类 `tax_payment`，置信度 `high`
- 如果 `备注` 含“基本医疗保险”“失业保险”“社保”等关键词：归类 `salary_social_tax`，置信度 `high`

### B. `代发工资`

- 直接归类 `salary_social_tax`，置信度 `high`
- 如果对方户名为空，业务分类仍可判定，但应进入人工复核，确认工资明细和分摊口径

### C. `存款利息`

- 直接归类 `interest_income`，置信度 `high`

### D. `汇款汇入` + `用途=股东注资`

- 直接归类 `capital_injection`，置信度 `high`
- 仍建议人工复核资本金口径和正式会计处理方式

### E. `网上汇款` / `汇款汇出`

- 如果 `用途` 或 `备注` 含“报销”：归类 `staff_reimbursement`，置信度 `high`
- 如果 `用途` 或 `备注` 含“房租”：归类 `vendor_payment`，置信度 `high`
- 如果对方为“北京住房公积金管理中心”：归类 `salary_social_tax`，置信度 `high`

### F. `网络转入` / `跨行代付`

- 如果 `用途` 或 `备注` 含“打款验证”，且金额极小：归类 `verification_deposit`，置信度 `high`
- 如果只是支付平台小额来款但业务目的不明：归类 `verification_deposit`，置信度 `medium`

### G. `银联B2B网关支付`

- 如果对方银行为“支付机构备付金集中存管账户”且对方户名为个人：优先归类 `other_or_unknown`
- 这类交易当前应强制人工复核，不建议直接进入稳定科目映射

## 建议人工复核触发条件

以下任一情况，建议 `requires_manual_review = true`：

- 个人户名收付款但摘要不清
- 同时命中多个业务类别
- 大额异常交易
- 与历史规则冲突
- 缺少对方户名或摘要
- 内部转账无法确认内部账户
- 涉及退款、赔付、补偿、冲销等复杂场景
- 股东注资、资本金投入等需要正式口径确认
- 支付机构备付金账户相关支出但业务用途不明
- 工资批量代发但缺少对方明细
- 股东注资、资本金投入等需要正式口径确认
- 支付机构备付金账户相关支出但业务用途不明
- 工资批量代发但缺少对方明细

## 建议输出示例结构

```text
business_type_candidate: staff_reimbursement
classification_confidence: medium
classification_basis: 对方户名为个人，摘要包含“报销”，方向为流出
requires_manual_review: true
manual_review_reason: 未匹配到员工名单，需确认是否为员工报销
```

## 最低通过标准

要进入“分录草稿生成”阶段，建议至少满足：

- 业务分类明确
- 有清晰的判断依据
- 已输出置信度
- 低置信度项目已标记人工复核
